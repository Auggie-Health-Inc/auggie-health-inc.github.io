The simulator owns truth, the model only narrates: an event-sourced architecture that keeps large language models out of canonical patient state in clinical simulation

Pulkit Singhal

Augmented Intelligence, Vol. 1 · Published 2026-11-15

Download PDF

Abstract

Background. Large language models (LLMs) are being rapidly adopted as virtual patients and conversational tutors in clinical education. In the common design, the model itself holds the patient's state and improvises the clinical facts of the case. Because LLMs hallucinate, this places fabricated clinical facts directly into the authoritative record a learner reasons against — a safety and validity problem that prompt engineering alone cannot close.

Objective. To describe and justify an architecture that makes it structurally impossible for the model to mutate canonical patient state, while still using the model for what it is good at: natural-language narration. We claim no new algorithm; the contribution is a specific, testable architectural discipline for clinical simulation and the reasons it holds.

Design. A deterministic, event-sourced core owns truth. Every user action becomes an event; a pure, total state engine folds events into patient state via apply_event/replay; the resulting state is handed to the LLM only as a read-only narration input. The append-only event log is the single source of truth and the materialized patient state is a cache that replay can always rebuild. The determinism invariant — replaying the same event log yields identical state — is encoded as an executable test rather than a hoped-for property. Probabilistic physiology is resolved upstream and recorded as event payloads so the reducer stays deterministic. Canonical truth is hidden and disclosed in stages; the learner and the narrator see only what the simulator chooses to reveal.

Significance. The model cannot write a clinical fact into the record it should not, because it has no write path to canonical state; it can still mis-narrate, but it cannot corrupt the truth the learner is graded against or the audit log. Determinism makes runs reproducible and reviewable. The pattern is a design discipline others can adopt and test, positioned against the dominant LLM-holds-state approach. We do not claim a learning-outcome result here; this is an architecture report, not an efficacy trial.

1. Introduction

Large language models are being adopted quickly in medical education as virtual patients, standardized-patient simulators, and conversational tutors; recent scoping reviews catalog dozens of such systems [1,2]. The appeal is obvious: an LLM can hold a fluent, open-ended clinical conversation that scripted branching simulations cannot.

In the most common design, the LLM is the simulation. It is prompted with a case sketch and then improvises the patient's answers, the vital signs, the lab values, and the course of the illness as the conversation unfolds. This is also where the danger lives. LLMs hallucinate, and in clinical contexts they do so in ways that are both confident and plausible [3,4]. When the model holds the state, a hallucinated potassium value, an invented allergy, or a silently shifted diagnosis is not a cosmetic error — it becomes the canonical fact the learner reasons against and is assessed on. Prompt engineering can reduce the rate of such errors but cannot make them impossible, because the authoritative state and the stochastic text generator are the same component.

This article describes an alternative that we have found load-bearing in building a clinical simulation platform: separate the thing that owns truth from the thing that talks. A deterministic engine computes patient state; the LLM only turns already-computed state into prose. The contribution is not a new technique — separating a verified state from a language model, and event sourcing as a way to hold authoritative state, are both established (Section 2). The contribution is the specific, testable discipline for the clinical-simulation case, and the argument for why it closes the hallucination-into-the-record hole that the mainstream design leaves open.

2. Related work

LLM virtual patients. A large and growing body of work uses LLMs as virtual or standardized patients and as tutors [1,2]. These systems demonstrate the conversational value of LLMs in education; most of them, however, let the model carry the clinical state of the case, which is exactly the design decision this article argues against.

Clinical hallucination. The tendency of LLMs to produce confident, fabricated clinical content is well documented, including under adversarial conditions and in summarization, and has motivated dedicated safety and hallucination-rate frameworks [3,4]. Our architecture is a structural response to this hazard for the simulation case specifically.

Keeping the model out of authoritative state. The general principle of pairing an LLM with an external, structured state rather than letting it be the state is established. Generative-agent architectures give LLM agents an external memory stream and retrieval rather than relying on the model's own memory [5]; neuro-symbolic approaches constrain LLM behavior with explicit procedural structure for adherence and interpretability [6]; and deterministic event-graph substrates have been proposed as world models for structured reasoning over simulated state [7]. Our work applies this principle in a particular, strict form — the LLM has no write path to canonical state at all — to clinical education.

Event sourcing. Representing authoritative state as an append-only log of events, with current state derived by replaying that log, is a standard software-architecture pattern [8]. We adopt it unchanged; our contribution is using it as the enforcement mechanism for the truth/narration boundary and encoding its determinism as a test.

Against this prior art we add no algorithm. We add a concrete, testable architecture for clinical simulation that makes model-corruption of canonical patient state structurally impossible, and the rationale for each boundary.

3. The architecture

3.1 The one rule

User Action → Event → State Transition → Patient State Update → LLM Narration → User

The LLM never directly mutates canonical patient state. It receives a state the deterministic engine has already produced and turns it into prose. Every layer exists to protect that boundary: the model is a read-only consumer of finished state, sitting behind a provider-agnostic boundary and never imported into the engine.

3.2 Event sourcing: the log is the truth

An append-only events log is the single source of truth. Current patient state is a materialized projection — a cache produced by a pure function, replay(events) → PatientState. Because replay is pure, the cached snapshot can be dropped and rebuilt at any time and is never authoritative on its own.

events (append-only)  ──replay()──▶  PatientState snapshot  ──narrate()──▶  prose
        ▲                                                         (read-only)
        │ apply_event() folds one validated event at a time
   new event (from a validated user action)

This has three consequences that matter for safety. The history is complete and auditable: every change to the patient is an event with a cause. The state is reconstructable: nothing is lost if a cache is corrupted. And, critically, there is no API by which the narrator can append an event — only validated user actions and engine decisions produce events.

3.3 The state-engine contract

The engine that folds events into state is held to an explicit contract:

  • Pure: no clock reads, randomness, I/O, network, or LLM calls.
  • Total: every event type has an explicit branch; an unknown type raises rather than being silently ignored.
  • Ordered and idempotent: events fold in monotonic order; a non-monotonic sequence is rejected so replay is reproducible.
  • Probabilistic physiology resolved upstream: when an outcome is stochastic (a complication, a lab draw), the randomness is resolved before the event is recorded and the result is written into the event payload. The reducer itself stays deterministic, so the same log always yields the same state.

Keeping the engine pure is what lets the determinism invariant be tested at all, and it is what keeps every clinical decision — selection, scoring, disclosure — in typed business logic rather than in a free-text prompt.

3.4 The determinism invariant as a test

The property that the whole design rests on — replaying the same event log yields identical state — is encoded as an executable test, not left as an aspiration. That test is the operational statement of the safety claim: if it passes, the patient's truth is a deterministic function of a reviewable log, independent of the model. A regression that let non-determinism (or the model) into the write path would turn the test red.

3.5 Hidden truth and staged disclosure

The case's canonical truth is stored hidden; the learner and the narrator only ever see what the simulator chooses to reveal at each step. This supports the teaching goal — preserve uncertainty until the learner commits — and it also means the model is never handed the full answer key to leak.

4. Why this is safe, and what it is not

What the architecture guarantees. The model cannot write a clinical fact into the canonical record, because it has no write path to it. A hallucinated value in the model's prose is a narration error, visible and correctable, not a corruption of the state the learner is assessed against or of the audit log. Runs are reproducible and reviewable because state is a pure function of an append-only log.

What it does not guarantee. The model can still mis-narrate — describe the computed state inaccurately or add unsupported color. Our claim is narrower and, we think, the right one: the model cannot corrupt truth, only its telling, and a telling error is recoverable in a way a corrupted record is not. Narration-layer accuracy (faithfulness of prose to state) is a separate, ongoing concern and is not solved by this architecture.

What we do not claim. We claim no new algorithm; event sourcing [8], external-state agent design [5,6,7], and LLM virtual patients [1,2] are all prior work. We present no learning-outcome or efficacy result here; this is an architecture and rationale report, and an efficacy study is future work. The description is of one system's design; other decompositions could enforce the same boundary.

5. Implementation / Contact / Code

The pattern is deliberately portable: an append-only event store, a pure reducer, a test that asserts replay-identity, and a narration layer that only reads. It does not depend on a particular model provider — the LLM sits behind a provider-agnostic boundary — or on a particular database; an in-memory store and a durable store satisfy the same interface. A reference description and the determinism test are available for reuse; implementation questions are welcome via the project's issue tracker.
